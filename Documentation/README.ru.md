**Unofficial driver for Nothing audio devices** управляет наушниками Nothing и CMF из macOS: шумоподавление и его уровень, пресеты и полосы эквалайзера, бас, пространственный звук, жесты, кодек, заряд, детекция в ухе, подключение к двум устройствам, поиск наушников. В окне настоящего приложения и со значком в строке меню — для того, что делаешь не глядя.

Оно ничего не скачивает, ничего не раздаёт по localhost и не открывает браузер. Протокол реализован здесь, на Swift: кадры, CRC16, словарь команд, возможности моделей и полосы прошивок.

## Откуда это взялось

Протокол устройства никто не публиковал. Он выведен чтением исходников [ear (web)](https://github.com/radiance-project/ear-web) — отличного открытого веб-драйвера под AGPL-3.0, развёрнутого на [earweb.bttl.xyz](https://earweb.bttl.xyz), — и затем сверен с живым железом, кадр за кадром.

Ранние версии этого проекта были оболочкой вокруг того интерфейса: брали веб-драйвер как есть и подкладывали под него транспорт, которого нет в WebKit, — сайт говорит через **Web Serial поверх Bluetooth SPP**, а ни один WebKit-вью такого API не реализует. Версии 1.0.0 он больше не нужен. Интерфейс свой, слой протокола свой, и при обычном запуске с их развёртывания не скачивается ничего.

Их интерфейс остался в одном флаге запуска — `--web`, — потому что покрывает модели и функции, до которых нативный экран пока не дорос. В этом режиме, и только в нём, приложение загружает интерфейс с развёртывания авторов на вашу машину, ровно как раньше.

**Ни одного их файла нет ни в репозитории, ни в бандле**, и CI роняет сборку, если такой файл там появится. Лицензия здесь AGPL-3.0 по выбору, а не по обязанности — см. [Лицензию](#лицензия).

## Что оно умеет

**Само говорит на протоколе.** Словарь на 84 команды, 23 модели и 63 записи опознания; возможности и раскладки жестов хранятся данными, а не ветками в коде. 42 команды подтверждены живым устройством, остальные выведены из чужих исходников и помечены в словаре именно так.

**Нативный экран.** Три вкладки — «Звук», «Наушники», «Управление» — свёрстанные под окно фиксированного размера, по-русски или по-английски, с переключением на лету. Светлая и тёмная тема следуют системе или закрепляются в приложении.

**Значок в строке меню.** Заряд и режим прослушивания без открытия окна: левый клик меняет шумоподавление и его уровень, правый открывает остальное.

**Настоящий транспорт Bluetooth.** Приложение находит через SDP кастомный SPP-сервис устройства, открывает канал RFCOMM и само собирает кадры протокола. Когда наушники закрывают канал по простою, оно молча переоткрывает его и досылает нажатое. Выход любым способом отпускает канал: устройство отдаёт его одной программе за раз.

## Чего оно не умеет

Оно не поддерживает ни одного устройства, которого нет в конфигурации авторов интерфейса. С железом сверена ровно одна модель — **Nothing Headphone (1)**; всё остальное лежит данными, вычитанными из их исходников, и живого устройства не видело. Сообщения про конкретные модели приветствуются, захваты — тем более.

Приложение не подписано Apple. Релизы подписаны ad-hoc и не нотаризованы.

## Требования

- macOS 13 или новее, Apple Silicon или Intel
- Инструменты командной строки Xcode (`swiftc`, `codesign`, `iconutil`)
- Наушники, уже сопряжённые в Системных настройках → Bluetooth
- Устройство Nothing или CMF

## Сборка

```bash
git clone https://github.com/Letsrollamigo/nothing-audio-driver-macos.git
cd nothing-audio-driver-macos
./build.sh
open "build/Unofficial driver for Nothing audio devices.app"
```

Это вся сборка: ни пакетного менеджера, ни проекта Xcode, ни зависимостей — `build.sh` компилирует исходники, собирает универсальный бандл и подписывает его.

| Команда | Что делает |
|---|---|
| `./build.sh` | Собрать в `build/` |
| `./build.sh --test` | 210 проверок протокола и правил путей, железо не нужно |
| `./build.sh --install` | Собрать и положить в `/Applications` |
| `SITE_SRC=/путь/к/site ./build.sh` | Вшить копию веб-интерфейса, которая у вас уже есть, — для `--web` |
| `SITE_SRC=none ./build.sh` | Собрать без неё (так же по умолчанию, если копии не нашлось) |

### Подпись и зачем она нужна

macOS выдаёт доступ к Bluetooth через TCC, а TCC узнаёт приложение по подписи. При ad-hoc подписи отпечаток меняется на каждой сборке, поэтому **система будет спрашивать разрешение после каждой пересборки**. Самоподписанный сертификат снимает это навсегда:

1. Связка ключей → Ассистент сертификации → Создать сертификат
2. Имя `ear-local-dev`, тип идентификации **Самоподписанный корневой**, тип сертификата **Подпись кода** — по умолчанию там S/MIME, он не подойдёт
3. Собрать с ним:

```bash
CODESIGN_ID=ear-local-dev ./build.sh --install
```

Разрешите Bluetooth один раз при первом запуске — дальше разрешение переживёт и пересборки, и переименование, и переезд в `/Applications`.

## Как устроено

| Часть | Файл | Задача |
|---|---|---|
| Кодек | `Sources/NothingProtocol.swift` | Кадр, CRC16-Modbus, роли, нарезка потока, разбор полей |
| Каталог | `Sources/NothingCatalog.swift` | Команды, модели, возможности, раскладки жестов — генерируется, руками не правится |
| Экран | `Sources/NativeScreen.swift` | Окно, вкладки, значок в строке меню, транспорт для представлений |
| Строки | `Sources/Localisation.swift` | Русский и английский одной таблицей, переключение в рантайме |
| Мост | `Sources/main.swift` (`SerialBridge`) | Поиск сервиса по SDP, канал RFCOMM, сборка кадров, переподключение, очередь |

Каталог собирается из конфигурации авторов интерфейса скриптом, который остаётся на машине автора: ему нужна локальная копия их сайта, а сюда попадает результат — числа, а не код.

Ещё два файла обслуживают только `--web`: `Sources/shim.js` — девять членов Web Serial API поверх `webkit.messageHandlers`, и `Sources/SiteUpdater.swift` — зеркалирование и чистка копий интерфейса. Этот путь описан в [ARCHITECTURE.md](ARCHITECTURE.md); документ написан до нативного слоя и рассказывает только про оболочку, шим и транспорт.

## Известные ограничения

**Первый запуск требует свежеподключённых наушников.** Канал опознания, сообщающий модель, одноразовый: устройство отдаёт его только сразу после подключения. Приложение кэширует ответ по адресу устройства и дальше пользуется кэшем, но самый первый запуск на конкретном устройстве обязан поймать его вживую. Без модели контролы, зависящие от возможностей, — уровень шумоподавления, раскладка жестов — просто не появятся.

**Проверена одна модель.** См. выше: всё, кроме Nothing Headphone (1), — выведенное знание.

**Релизы не нотаризованы.** Учётной записи разработчика Apple за проектом нет, поэтому со скачанной сборки нужно один раз снять карантин через `xattr -d com.apple.quarantine`, а её ad-hoc подпись заставит macOS переспрашивать доступ к Bluetooth после каждого обновления. Локальная сборка со своим сертификатом снимает обе проблемы.
