**Unofficial driver for Nothing audio devices** — нативное приложение macOS для управления наушниками Nothing и CMF: шумоподавление, эквалайзер, жесты, заряд, версия прошивки. Без браузера.

Появилось из-за одного факта: прекрасный драйвер [ear (web)](https://github.com/radiance-project/ear-web) общается с наушниками через **Web Serial поверх Bluetooth SPP**, а в WebKit такого API нет вовсе. Ни Safari, ни WKWebView его не запустят. Поэтому приложение берёт их интерфейс как есть и подкладывает под него собственный транспорт — нативный мост `IOBluetooth` RFCOMM под видом `navigator.serial`.

Итог: тот же интерфейс, но в окне настоящего приложения — без Chromium, без docker, без локального веб-сервера.

## Чей тут вклад

Всё, что знает что-либо о наушниках, — не отсюда. Протокол, конфигурация моделей, привязка возможностей к версиям прошивок, все 19 экранов устройств — работа авторов [ear (web)](https://github.com/radiance-project/ear-web), опубликованная под AGPL-3.0 и развёрнутая на [earweb.bttl.xyz](https://earweb.bttl.xyz).

Этот репозиторий добавляет обвязку на три файла и **не содержит ни одного их файла**. При первом запуске приложение само загружает интерфейс с их развёртывания на вашу машину и дальше хранит локальную копию, чтобы работать без сети.

> **Куда сообщать об ошибках.** Если не работает элемент управления, не опознаётся модель или врёт полоса эквалайзера — это к ним: [radiance-project/ear-web/issues](https://github.com/radiance-project/ear-web/issues). Сюда — только про сторону macOS: мост Bluetooth, окно, подпись, разрешения, обновление.

## Что оно даёт

**Настоящее приложение** — иконка в доке, своё окно, запуск как у всего остального. Ни вкладки, ни localhost, ни контейнера.

**Нативный транспорт Bluetooth** — приложение находит через SDP кастомный SPP-сервис устройства, открывает RFCOMM-канал и само собирает кадры протокола. Когда наушники закрывают канал по простою, оно молча переподключается и досылает то, что вы нажали.

**Работу без сети** — интерфейс лежит на диске после первой загрузки. Чтобы переключить режим шумоподавления, интернет не нужен.

**Тихие обновления** — при запуске копия сверяется с живым сайтом по `Last-Modified` и размеру, при расхождении скачивается свежая, а на диске остаётся ровно одна.

## Чем оно не является

Это не форк, не зеркало и не перераспространение ear (web). Своей поддержки устройств оно не добавляет: если модель не поддержана у них, здесь она тоже работать не будет. Приложение не подписано Apple — вы собираете и подписываете его сами.

## Требования

- macOS 13 или новее, Apple Silicon или Intel
- Инструменты командной строки Xcode (`swiftc`, `codesign`, `iconutil`)
- Наушники, уже сопряжённые в Системных настройках → Bluetooth
- Устройство Nothing или CMF, поддержанное авторами интерфейса

## Сборка

```bash
git clone https://github.com/Letsrollamigo/nothing-audio-driver-macos.git
cd nothing-audio-driver-macos
./build.sh
open "build/Unofficial driver for Nothing audio devices.app"
```

Это вся сборка: ни пакетного менеджера, ни проекта Xcode, ни зависимостей — `build.sh` компилирует два файла на Swift, собирает бандл и подписывает его.

| Команда | Что делает |
|---|---|
| `./build.sh` | Собрать в `build/` |
| `./build.sh --test` | Прогнать проверку нормализации путей |
| `./build.sh --install` | Собрать и положить в `/Applications` |
| `SITE_SRC=/путь/к/site ./build.sh` | Вшить копию интерфейса, которая у вас уже есть |
| `SITE_SRC=none ./build.sh` | Собрать без неё (так же по умолчанию, если копии не нашлось) |

### Подпись и зачем она нужна

macOS выдаёт доступ к Bluetooth через TCC, а TCC узнаёт приложение по подписи. При ad-hoc подписи отпечаток меняется на каждой сборке, поэтому **система будет спрашивать разрешение после каждой пересборки**. Самоподписанный сертификат снимает это навсегда:

1. Связка ключей → Ассистент сертификации → Создать сертификат
2. Имя `ear-local-dev`, тип идентификации **Самоподписанный корневой**, тип сертификата **Подпись кода** — по умолчанию там S/MIME, он не подойдёт
3. Собрать с ним:

```bash
CODESIGN_ID=ear-local-dev ./build.sh --install
```

Разрешите Bluetooth один раз при первом запуске — дальше разрешение переживёт и пересборки, и переименование, и переезд в `/Applications`.

## Как устроено

| Часть | Файл | Задача |
|---|---|---|
| Оболочка | `Sources/main.swift` | Окно, `WKWebView`, раздача интерфейса по приватной схеме `earlocal://` |
| Мост | `Sources/main.swift` (`SerialBridge`) | Поиск сервиса по SDP, канал RFCOMM, сборка кадров, переподключение, очередь |
| Шим | `Sources/shim.js` | Девять членов Web Serial API поверх `webkit.messageHandlers` |
| Обновление | `Sources/SiteUpdater.swift` | Проверка, зеркалирование, чистка старых копий |

Сам интерфейс не правится ни на строку: их JavaScript продолжает звать `navigator.serial.requestPort()` и не догадывается, что порт под ним — вовсе не порт.

Подробности архитектуры и протокола: [ARCHITECTURE.md](ARCHITECTURE.md).

## Известные ограничения

**Первый запуск требует свежеподключённых наушников.** Канал опознания, сообщающий модель, одноразовый — устройство отдаёт его только сразу после подключения. Приложение кэширует ответ и дальше пользуется кэшем, но самый первый запуск на конкретном устройстве обязан поймать его вживую.

**Только то, что поддержано авторами интерфейса.** Новые модели появляются тогда, когда появляются у них.

**Релизы не нотаризованы.** Учётной записи разработчика Apple за проектом нет, поэтому со скачанной сборки нужно один раз снять карантин через `xattr -d com.apple.quarantine`, а её ad-hoc подпись заставит macOS переспрашивать доступ к Bluetooth после каждого обновления. Локальная сборка со своим сертификатом снимает обе проблемы.
